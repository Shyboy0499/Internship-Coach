# Internship Notebook and Weekly Check-in

A short file that gives Claude memory across conversations, plus a weekly routine that keeps it current.

## Why keep a notebook

Interns are told to keep notes and a work log; most don't. The notebook does it for them, and it lets Claude remember what matters between conversations: the mentor's communication preferences, the goals agreed in week one, feedback received, and what the intern actually delivered. Later requests — a midpoint self-review, the final presentation, the return-offer conversation, resume bullets — then rest on real evidence instead of guesswork, and the intern doesn't have to repeat themselves.

## Ask first

Create the notebook only after the intern agrees. Offer it once, at a natural moment — early in the internship, during a weekly check-in, or when they share something worth remembering — not in every answer:

> Want me to keep a short internship notebook in this folder, so I can remember your goals, how your mentor likes to communicate, and what you've done each week? It stays on your computer, and you can ask me to delete it any time.

If they decline, carry on without it and don't ask again in the same conversation.

## Where it lives

- **With file access** (Claude Code, the Claude desktop app, the Agent SDK): `internship-notebook.md` in the current working folder. When this skill is in use, check whether the file exists and read it before answering.
- **Without lasting file access** (an ordinary chat): offer the same content as a block the intern can paste into their own notes app, and suggest they paste it back at the start of the next conversation.

## Notebook format

```markdown
# Internship notebook

## Basics
- Role and team:
- Dates: [start] to [end]
- Mentor / manager: [first name or role]
- How they like to communicate: [e.g. chat for quick questions, batch the rest for the Thursday 1:1]
- Remote, hybrid, or in person:

## Goals and success criteria
- [What a great internship looks like, in the mentor's words]
- [Personal goals]

## Feedback received
- [date] [feedback] → [what I changed]

## Work log
### Week of [date]
- Did: [task] → Result: [outcome, number, or who it helped]
- Learned: [...]
- Thanks owed: [person, for what]

## Questions to batch for the next 1:1
- [...]

## Return offer
- [What the manager said it would take, and current status]
```

## Using the notebook

- **Read it first** and use what's there — don't re-ask for facts it already holds.
- **Update it** when the intern shares something durable: a mentor preference, a goal, feedback, an accomplishment, a decision. Mention it in one short line ("Added that to your notebook.").
- **Build on it** for self-reviews, final presentations, handoff docs, and resume bullets. Use the actual entries; never invent accomplishments, numbers, or feedback that aren't there.
- **Keep it work-safe.** Short factual notes only. No gossip or personal details about colleagues, and no confidential material (customer data, unreleased numbers, credentials, internal code).
- **Forget on request.** If the intern asks to delete or forget it, delete the file and confirm.

## Weekly check-in

Use this when the intern asks for a weekly check-in, a Friday review, or help writing their weekly update — or offer it at the end of a week.

1. **Gather.** Read the notebook if there is one. Then ask, in one short message rather than an interview: what they worked on, anything blocked, any feedback this week.
2. **Log.** Write this week's work-log entry: Did → Result, Learned, Thanks owed.
3. **Update.** Draft the weekly update for the mentor (the "Weekly update" template in `templates.md`), in the mentor's preferred channel and format. Put blockers and anything the mentor needs to act on near the top.
4. **Look ahead.** Name one thing to do better next week — drawn from feedback received or the core habits — and any risk worth flagging now rather than later.
5. **Batch.** Move non-urgent questions into the notebook's list for the next 1:1.

Keep the whole check-in to about one screen. If the notebook exists, save the new entries to it.
